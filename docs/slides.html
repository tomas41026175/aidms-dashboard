const CONSECUTIVE = 3   // 3 點 × 2s = 6 秒窗口

const lastN = history.slice(-CONSECUTIVE)
const levels = lastN.map(m =>
  classifyValue(extractor(m), thresholds)
)

// 條件 A：全部 critical → critical
if (levels.every(l => l === 'critical'))
  return 'critical'

// 條件 B：無一 normal（至少 warning）→ warning

return 'normal'   // 任一點回到 normal 即解除

// SSE JSON.parse 後是 unknown
// TypeScript 只在編譯期保護你
function isValidMetrics(
  data: unknown
): data is SystemMetrics {
  if (typeof data !== 'object') return false
  const d = data as Record<string, unknown>
  if (typeof d.cpu?.usage !== 'number')
    return false
  if (!Array.isArray(d.disk)) return false
  return true  // TypeScript narrowing ✓
}

ChartComponents — Parameter Design WHY

參數設計理由

WHY labels 與 datasets 分開？

labels 是共用的 x 軸，不屬於任何一條線。若放進 dataset，多條線時要重複傳，且不同 dataset 的 labels 不一致時容易出錯。

❌ datasets: [{ labels, data }, { labels, data }] ← 重複 ✅ labels + datasets: [{ data }, { data }] ← 單一來源

WHY curve: 'smooth' 不用 'monotoneX'？

消費者的心智模型是「平滑 / 直線 / 階梯」，MUI 的命名是內部插值算法名稱。Transform 層吸收這層認知差距，消費者不需要知道 MUI 的實作細節。

WHY yRange: [0, 100] 不用 {min, max}？

tuple 比 object 少打字，且視覺上一眼看出「範圍」的概念。監控場景 99% 是 [0, 100]，tuple 降低常見操作的噪音。

WHY layout 不拆成兩個元件？

BarChart vertical 與 horizontal 的資料結構完全相同，差異只在視覺方向。拆成 VerticalBarChart / HorizontalBarChart 會讓消費者記憶兩個 API，但其實只需要一個旗標。

WHY arc: 'half' | 'full' 不直接傳角度？

MUI Gauge 的 startAngle / endAngle 是實作細節。消費者說「我要半圓儀表」，不需要知道 -110°~110°。ARC_MAP 把業務語義與 MUI API 解耦，未來調整角度只改一處。

WHY color 支援函式？

告警顏色是業務邏輯（CPU >85% = red），不是套件的職責。若套件預設 warnAt / criticalAt 參數，就把業務語義耦合進圖表套件。函式讓消費者自己決定何時變色，套件保持中立。

// 業務邏輯留在 Dashboard，不在套件
function alertColor(v: number) {
  if (v > 85) return '#f87171'
  return '#34d399'
}
<GaugeChart color={alertColor} />

WHY data: (number | null)[]？

SSE 連線初始時沒有歷史資料，這是真實狀態，不是錯誤。用 null 而非 0 保留語義差異：null = 尚無資料，0 = 量測到零。MUI 對 null 的處理是折線斷點，視覺上正確。

WHY animate 預設 true，但 Dashboard 傳 false？

套件作為通用元件，動畫預設開啟（初次渲染好看）。但 SSE 每 2 秒更新時，動畫會重播 → 視覺抖動。消費者根據使用場景決定，套件不假設使用情境。

LTTB 演算法

傳統等距取樣： 原始: ─────∧──────────/── 等距: ── ─ ─ ─ ─ ← spike 被取到空白處 LTTB：每 bucket 取三角形面積最大的點 A = 前一個選中點 B = 候選點 C = 下一個 bucket 平均（代理未來趨勢） 選 max(area(A,B,C)) ← 面積大 = 視覺重要

MVP 已實作優化

  • >30 點關閉 mark：減少 SVG DOM 節點
  • animate={false}：SSE 2s 更新時不重播動畫
  • useMemo datasets：穩定 reference，避免不必要 re-render
  • React.memo（TrendCharts）：同一 2s 週期內跳過中間 render
告警場景用 Min-Max 而非 LTTB — 確保 CPU spike 峰值不被抹除
