亮點 03 / 06

連續 3 點告警
防 Alert Storm · Cry Wolf Effect

const CONSECUTIVE = 3  // = 6 秒

export function deriveAlertLevel(
  history: SystemMetrics[],
  extractor: (m) => number,
  thresholds,
) {
  const lastN = history.slice(-CONSECUTIVE)
  const levels = lastN.map(m =>
    classifyValue(extractor(m), thresholds)
  )
  if (levels.every(l => l === 'critical'))
    return 'critical'
  if (levels.every(l => l !== 'normal'))
    return 'warning'
  return 'normal'
}

為什麼是 3 點？

  • 1 點 = Alert storm，cron/GC 每次都觸發，用戶無視所有告警
  • 3 點 = 6 秒 — 過濾短暫 spike，不延遲真告警
  • 5~10 點 = 10~20 秒，告警延遲太久，錯過處理窗口
CPU: W>70% C>85% MEM: W>75% C>90% DISK: W>80% C>90%
業界標準設定（參考 Grafana 預設 evaluation interval）— 告警是 domain knowledge，不是任意選的數字

Vite resolve.dedupe
Monorepo 雙實例問題

問題根因

DashboardApp └─ node_modules/@mui/x-charts ← ThemeProvider ✓ ChartComponents (file: 連結) └─ node_modules/@mui/x-charts ← 獨立實例！ 不在 ThemeProvider context 中 → 預設 light theme → 黑色文字 + 深色背景 = 不可見
視覺症狀：Gauge 圖表空白、LineChart 圖例文字消失、軸標籤不可見

解法

// vite.config.ts
export default defineConfig({
  resolve: {
    dedupe: [
      'react',
      'react-dom',
      '@mui/material',
      '@mui/x-charts',   // 關鍵
      '@emotion/react',
      '@emotion/styled',
    ],
  },
})
強制所有模組（含 file: 連結的套件）共用同一份 MUI 實例，ThemeProvider context 正確傳遞

① Runtime 型別守衛

// SSE JSON.parse 後是 unknown
// TypeScript 只在編譯期保護你
function isValidMetrics(
  data: unknown
): data is SystemMetrics {
  if (typeof data !== 'object') return false
  const d = data as Record<string, unknown>
  if (typeof d.cpu?.usage !== 'number')
    return false
  if (!Array.isArray(d.disk)) return false
  return true  // TypeScript narrowing ✓
}
解法：type predicate data is SystemMetrics — 不用 any，讓 TS 理解 narrowing

LTTB 演算法

傳統等距取樣： 原始: ─────∧──────────/── 等距: ── ─ ─ ─ ─ ← spike 被取到空白處 LTTB：每 bucket 取三角形面積最大的點 A = 前一個選中點 B = 候選點 C = 下一個 bucket 平均（代理未來趨勢） 選 max(area(A,B,C)) ← 面積大 = 視覺重要

MVP 已實作優化

  • >30 點關閉 mark：減少 SVG DOM 節點
  • animate={false}：SSE 2s 更新時不重播動畫
  • useMemo datasets：穩定 reference，避免不必要 re-render
  • React.memo（TrendCharts）：同一 2s 週期內跳過中間 render
告警場景用 Min-Max 而非 LTTB — 確保 CPU spike 峰值不被抹除
